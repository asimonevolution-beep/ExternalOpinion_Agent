```
report singolo → pacchetti → SaaS → API → white-label → enterprise
```

---

## LEGGE OPERATIVA SUPERIORE

Ogni scelta deve servire questa catena:

```
cliente → problema → traffico → lead → pagamento → report/prodotto → incasso
```

Se una proposta, modulo, automazione o sviluppo non serve direttamente questa catena
nella fase attuale, viene **archiviato** — non cancellato, non svalutato, ma non comanda.

---

## FASI ECONOMICHE E GATE

| Fase | Obiettivo | Gate di uscita |
|------|-----------|----------------|
| **Fase 0** | Primo incasso reale | 10 report venduti OPPURE €1K MRR reale |
| Fase 1 | Validazione | Clienti ricorrenti + domanda reale dati |
| Fase 2 | SaaS ricorrente | Richiesta API da cliente/partner reale |
| Fase 3 | Integrazione API | MRR stabile + lead enterprise qualificato |
| Fase 4 | Enterprise/scala | €50K+ MRR |

**FASE 0 COMANDA FINCHÉ NON ESISTONO INCASSI REALI.**

## RUOLO DI CASCADE

CASCADE è il motore tecnico del progetto.
**Non è la direzione commerciale.**
Serve il funnel, automatizza la consegna, aumenta potenza quando l'incasso lo richiede.

---

## FUNNEL PRINCIPALE (FASE 0)

```
landing → form → pre-analisi → paywall → pagamento → report → consegna → incasso
```

---

## MODULI FUTURI (GATE ECONOMICI)

Attivabili solo dopo il superamento dei gate:
- SaaS / dashboard / subscription / multi-tenant
- AVM evoluto, forecast, RAG documentale
- Developer portal, API pubbliche, widget embed
- White-label, banche, NPL, portfolio massivi

---

## PRINCIPIO PTS (PROGRESSO TECNOLOGICO SEMPLIFICATO)

Ogni tecnologia entra solo se **SEMPLIFICA** la catena verso l'incasso:
- meno passi
- meno costo
- meno attrito

Una tecnologia che aggiunge complessità senza togliere passi al cliente è vietata,
anche se potente. Si copiano percorsi già validati da altri, non si inventa.
